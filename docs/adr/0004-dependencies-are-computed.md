# Dependencies are a computed blocked state, not a status

O uso diário depende de dependências (uma issue foi desbloqueada ao fechar seu bloqueador em 15-08-2026), então o mt precisa do conceito — mas modelado como o deferral (ADR-0002): um campo `blocked_by` no frontmatter listando IDs de issues do mesmo vault, e uma issue está **blocked** se, e somente se, alguma issue listada não está `done`. Não existe status `blocked`, transição nem operação de "unblock": fechar o bloqueador desbloqueia sozinho, e reabrir um bloqueador rebloqueia sozinho. O nd guardava as duas direções (`blocked_by` e `blocks`) e um status `blocked` na sequência; aqui a direção é única (a issue registra quem a bloqueia) e o estado é computável. Referências são restritas ao mesmo vault para que `check` valide existência, ausência de auto-bloqueio e ausência de ciclos. `dep add`/`dep rm` editam o campo; `list` marca issues bloqueadas, `ready` e `pick-next` as pulam. Consequência: disponibilidade vira função do estado dos bloqueadores, e o Git (diffs do frontmatter) é o histórico das mudanças.
