# nd → mt: per-domain vaults, renamed IDs, backlog-first migration

A migração do vault nd vivo (`pkm/.vault`, 233 issues) cria **três vaults mt dentro do mesmo repo** — `bjd`, `dom` e `pes` (studies + conteudo + sem-área) — endereçados por bookmarks (consequência do ADR-0003), com todas as issues migradas, inclusive as 176 fechadas. Traduções: `closed` → `done` (+ `completed_at` = `closed_at`); `deferred` → `open` + `deferred_until` (ISO com Z e segundos → naive `YYYY-MM-DDTHH:MM`; valor só com dia → `T00:00`); `waiting` vira status customizado só no vault bjd; `in_progress` preservada sem `started_at` inventado. Comentários são preservados byte a byte (heading com autor + marcadores `beads-comment-id`); `deadline` vem do sidecar de beads (única cópia sobrevivente dos `due_at`); o corpo permanece intocado, inclusive linhas `Due:` históricas. Os IDs são renomeados por domínio — `pkm-055` → `bjd-055` — mantendo o sufixo (único no conjunto) e normalizando o case misto (`PKM-*`/`pkm-*`), e as referências a IDs no corpo são reescritas via mapa global para não virarem links mortos. Campos que o mt deliberadamente não tem são descartados: `assignee`, `type`, `priority`, `content_hash`, `updated_at`, `created_by`, `close_reason`, `blocks`, `parent`/epics — a seção `## History` preserva o registro. `blocked_by` é preservado (recurso do ADR-0004, implementado antes da migração). A ordem de prioridade não é migrável (labels `rank/{area}/NNN` são histórico ambíguo e o `nd list` nem ordena por rank): tudo entra no Backlog e a fila é reconstruída em uma passada manual de `mt prioritize` por vault. O branch `nd/backlog` é congelado como backup e as issues passam a ser trackeadas no `main`; `.nd.yaml` é removido e o `.gitignore` do `.vault` ajustado. Mecanismo: script Python idempotente em `pkm-nd-migration/scripts` (dry-run por padrão + `--apply`), com relatório de auditoria em `migration-artifacts/`.
